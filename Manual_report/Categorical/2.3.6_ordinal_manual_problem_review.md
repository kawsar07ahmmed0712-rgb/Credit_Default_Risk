# 2.3.6 Ordinal Categorical Manual Problem Review

This review checks each ordinal feature by feature meaning, not only by statistical route.

Main rule: ordinal features should preserve meaningful order. Rare levels are not automatically grouped, because a rare ordinal level can still carry important rank meaning.

## Feature-wise review

| Feature | Temporal Decision Check | Problem Found | Manual Correction |
|---|---|---|---|
| `NAME_EDUCATION_TYPE` | Mostly correct | No major decision problem. Temporal route correctly detected semantic order mapping. The only important note is that pandas category order is not the real educational order. | Use semantic order mapping: `Lower secondary < Secondary / secondary special < Incomplete higher < Higher education < Academic degree`. Keep rare `Academic degree`; do not group it. |
| `REGION_RATING_CLIENT` | Correct | No major problem. This is already numeric ordinal with stable train-test levels. | Keep as numeric ordinal candidate: `1 < 2 < 3`. No one-hot needed at this stage. |
| `REGION_RATING_CLIENT_W_CITY` | Partly correct | Temporal route correctly detected test-only special level `-1`, but risk became too high because `level_overlap_pct = 75%` was count-based. The `-1` level has tiny test mass, so this is not a strong distribution shift. | Keep numeric ordinal candidate for `1 < 2 < 3`, but handle `-1` as special/unknown before modeling. Manual risk should be medium, not high. |

## Main temporal logic problems found

1. `level_overlap_pct` alone is too sensitive for ordinal features with very few levels.
2. A tiny test-only special value can reduce overlap percentage sharply, but that does not always mean real instability.
3. Special numeric values like `-1` should not automatically be treated as part of the ordinal order.
4. For ordinal features, rare levels should usually be preserved if they have real rank meaning.
5. `NAME_EDUCATION_TYPE` requires manual semantic mapping, because lexical or pandas category order is not reliable.
6. `REGION_RATING_CLIENT` and `REGION_RATING_CLIENT_W_CITY` should stay numeric ordinal candidates, not one-hot by default.
7. No ordinal feature should be dropped at this stage.
8. Final usefulness must still be checked later with target relationship, multivariate redundancy, stability, and model validation.

## Corrected ordinal strategy

| Decision Area | Final Manual Rule |
|---|---|
| Education feature | Semantic ordinal mapping |
| Numeric region rating | Keep numeric ordinal |
| Test-only `-1` | Treat as special/unknown, not true ordinal rank |
| Rare ordinal levels | Preserve unless later evidence proves harmful |
| Drop decision | No drop in this EDA stage |
