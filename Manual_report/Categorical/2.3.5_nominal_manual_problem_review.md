# 2.3.5 Nominal Categorical Temporal Manual Problem Review

This review checks the temporal nominal categorical decisions feature-by-feature using feature meaning, not only statistical thresholds.

## Manual checking rule used

1. Take one feature at a time.
2. Understand the feature meaning.
3. Check whether the temporal route, risk, and manual-review decision match that meaning.
4. If the temporal decision is reasonable, skip the problem table.
5. If it is wrong or too aggressive, record the problem and corrected decision.

## Problems found and corrected

| Feature | Meaning used for manual check | Problem in temporal decision | Why it is wrong | Corrected manual decision |
|---|---|---|---|---|
| `CODE_GENDER` | applicant gender | Temporal logic treated category_overlap_pct=66.67 as weak overlap and raised stability risk. | This is wrong because the missing train-only level is XNA with almost zero mass; count-only overlap overstates risk. | Use binary-like gender encoding and handle XNA as unknown/missing; risk should be low. |
| `FONDKAPREMONT_MODE` | building capital repair fund mode | Possible route stayed as simple one-hot although missingness is very high. | For property-related mode features, missingness itself can carry information and must be explicit in the encoding route. | Use missing_as_category_then_one_hot; keep review for missing signal. |
| `HOUSETYPE_MODE` | house type / residence type | Route became low_information_candidate_validate_later too early. | The feature is dominated among non-missing values, but missingness may be useful; dominance alone should not become a drop-like decision. | Use missing_as_category_then_one_hot plus low-information validation later. |
| `NAME_FAMILY_STATUS` | family / marital status | manual_check_needed=True while risk is low and reason is standard_nominal_profile. | Family status is a meaningful low-cardinality business feature; tiny Unknown level is not a real risk. | Use normal one-hot with unknown-safe handling; no manual review needed now. |
| `NAME_HOUSING_TYPE` | housing arrangement | Rare grouping and top-overwhelming language was too aggressive. | House/apartment dominance is expected for this feature and does not make the feature problematic by itself. | Use one-hot; optional rare grouping later only if model pipeline needs it. |
| `NAME_INCOME_TYPE` | income source type | manual_check_needed=True even though risk is low and reason is standard. | Income type is a core low-cardinality credit feature; rare levels are tiny but meaningful. | Use one-hot with optional rare grouping for ultra-rare income types; no manual review now. |
| `NAME_TYPE_SUITE` | who accompanied the applicant | manual_check_needed=True with risk_score=0 and standard reason. | This is internally inconsistent; low missing and low rare mass do not require manual review. | Use missing_as_category_then_one_hot; no manual review needed now. |
| `OCCUPATION_TYPE` | applicant occupation | manual reason was standard_nominal_profile despite 31% missing and medium cardinality. | Occupation is meaningful, but missingness and rare job levels should be explicitly tracked. | Use missing_as_category_then_rare_group_then_one_hot; manual review needed. |
| `ORGANIZATION_TYPE` | employer organization / work sector | Route made compact encoding look primary. | The feature is high-cardinality, but categories are meaningful; rare-grouped one-hot can still be the primary baseline before supervised encoders. | Use rare_grouping_then_one_hot as primary; frequency/target encoding only candidate later. |
| `WALLSMATERIAL_MODE` | building wall material | Possible route stayed as simple one-hot although missingness is very high. | Property material feature has very high missingness, so missing category should be explicit. | Use missing_as_category_then_one_hot; review missing signal later. |

## Logic fixes to remember for future temporal cells

- Do not use category-count overlap alone; combine overlap with category mass.
- Do not trigger rare grouping only because `rare_count > 0`; rare mass and feature meaning must matter.
- For high-missing categorical property features, put `missing_as_category` inside the main encoding decision.
- `manual_check_needed=True` must have a real reason; it should not pair with `standard_nominal_profile`.
- High cardinality should not automatically make compact or target encoding the primary route.
- No nominal feature should be dropped at this stage without target, bivariate, multivariate, and model-validation evidence.
