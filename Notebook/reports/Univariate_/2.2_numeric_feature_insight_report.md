# 2.2 Numeric Feature Analysis — Research Report

## 1. Executive Summary

The numeric analysis covered **2,378 numeric features** from the profiling and temporal logic reports. The two input files were consistent: the feature counts matched, no duplicate features were found, and every numeric feature had a mapped numeric family and feature category.

The main conclusion is **not to mass-drop numeric features at this stage**. The numeric dataset is highly informative but sparse, skewed, and family-dependent. Decisions should be handled by numeric family: continuous features need transform/scaling review, count features need zero/activity/binning review, ratio features need boundedness and denominator-stability review, duration features need signed/special-value handling, and delay features should be preserved as credit-risk signal candidates.

## 5. Family-wise Research Findings

### 5.1 Continuous Numeric Features

Continuous features include amount, statistical aggregation, score/index, and normalized property features. This group has **608 features**, with **394 high-missing features**, **328 extreme-skew features**, and **29 high-outlier features**.

Research decision:
- Keep continuous features for now.
- Review missing indicators for sparse continuous features.
- Use `log1p` review only for non-negative skewed features.
- Use Yeo-Johnson review for signed skewed features.
- Use robust scaling or tail review for outlier-heavy features, especially for non-tree models.
- Do not apply transformations before target/model validation.

### 5.2 Discrete / Count Numeric Features

Count features have **600 features**. They should not be interpreted like ordinary continuous variables. Their most important meaning is activity depth: zero often means no activity/no history, and positive values represent historical behavior.

Dominant count-bin pattern:

| dominant_count_bin   |   feature_count |
|:---------------------|----------------:|
| missing              |             223 |
| zero                 |             206 |
| four_ten             |              44 |
| eleven_thirty        |              40 |
| one                  |              40 |
| two_three            |              34 |
| thirty_plus          |              13 |

Research decision:
- Keep raw count features initially.
- Add zero/non-zero or activity flag review for zero-heavy count features.
- Consider count binning for low-cardinality or strongly zero-dominated features.
- Review `not_integer_like_count` features because count features should generally be integer-like.
- Extreme count tails should be treated as activity-depth evidence, not automatically as bad outliers.

### 5.3 Ratio / Rate Numeric Features

Ratio/rate is the largest numeric family with **933 features**. Ratio features are sensitive because small denominators can create unstable or very large values.

Boundedness summary:

| bounded_type       |   feature_count |
|:-------------------|----------------:|
| bounded_0_1        |             576 |
| bounded_0_100      |             216 |
| signed_ratio       |              83 |
| unbounded_positive |              57 |
| non_positive       |               1 |

Research decision:
- Keep bounded 0–1 and 0–100 ratio features, but preserve their bounded interpretation.
- Review unbounded positive ratio features for denominator-driven tail instability.
- Review negative ratio features separately because they may be signed ratios or suspicious values.
- Use zero-ratio flag review where ratio values are heavily zero-dominated.
- Use capping/tail review only after model validation.

### 5.4 Date / Duration Numeric Features

Duration/time features have **93 features**. They are not ordinary continuous features because signed values can be meaningful, especially in Home Credit-style `DAYS_*` features.

Signed duration pattern:

| signed_pattern   |   feature_count |
|:-----------------|----------------:|
| mostly_negative  |              60 |
| mostly_positive  |              15 |
| other            |              15 |
| mixed_signed     |               3 |

Research decision:
- Keep signed duration direction until meaning is verified.
- Review days-to-years/months conversion for interpretability.
- Review duration binning for recency/history-depth signals.
- Review special placeholder values such as `365243` before imputation or transformation.
- Cyclical time features should be handled with cyclical encoding review if needed.

### 5.5 Delay / Overdue Numeric Features

Delay/overdue features have **144 features**, and all were review-relevant because delay information is credit-risk sensitive.

Delay evidence summary:

| metric               |   value |
|:---------------------|--------:|
| features             |     144 |
| late_signal          |     144 |
| early_payment_signal |      38 |
| severe_signal        |     119 |
| extreme_signal       |     128 |
| rare_severe_signal   |      72 |
| zero_heavy_delay     |      21 |

Research decision:
- Preserve delay/overdue features as potential credit-risk signals.
- Create or review late-payment flags, severe-delay flags, extreme-delay flags, and early-payment flags.
- Zero-heavy delay features should not be dropped automatically because zero can mean no delay/on-time behavior.
- Rare severe-delay signals are important candidates for feature engineering.
- Delay features should be validated carefully with target relation and cross-validation.

## 7. Final Feature Engineering Decision Framework

| Numeric Family | Recommended Route |
|---|---|
| `continuous` | Keep raw, review missing flags, transform/skew, scaling, and tail behavior |
| `discrete_count` | Keep raw, review activity flags, count bins, integer validity, and rare high-count tails |
| `ratio_rate` | Keep raw, review boundedness, zero-ratio flags, negative ratios, and denominator/tail instability |
| `date_duration` | Keep signed values, review placeholders, conversion to periods, and duration bins |
| `cyclical_time` | Keep separately, review cyclical encoding |
| `overdue_delay` | Preserve as credit-risk signal, review delay severity and sign-based flags |

## 8. What This Research Does Not Decide Yet

This numeric research does not make final feature dropping decisions. Final feature removal requires target relationship, leakage review, multicollinearity/redundancy review, and model validation.

It also does not apply transformations. It only defines **where transformation, scaling, binning, clipping, missing flags, and special-value handling should be reviewed**.
