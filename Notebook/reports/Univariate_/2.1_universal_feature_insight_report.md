| Decision Area | Universal Decision | Reason |
|---|---|---|
| ID column | Exclude from model, keep for tracking | `SK_ID_CURR` is an identifier, not a predictive feature |
| Target column | Exclude from feature set | `TARGET` is the label and is absent from test by design |
| Unknown categories | No immediate issue | All features were mapped into a predefined category |
| High missingness | Do not drop yet | Many missing values may represent history absence or sparse behavior |
| Train-test missing gap | Send to stability review | Features with large missing gaps may behave differently in test |

## Key Insight

Universal analysis shows that the integrated dataset is structurally ready for type-specific EDA. The main universal challenge is not feature mapping or duplicate structure; it is **sparse historical information**. A large number of features are missing-heavy because they come from linked historical sources such as bureau, installments, previous applications, POS cash, and credit card tables.

The correct next step is not dropping these features. The correct next step is to move into **type-specific analysis** and later decide whether missingness should become flags, source-availability indicators, or history-depth features.

## Next Step Route

| Feature Group | Next Analysis Route |
|---|---|
| Continuous amount/stat/score/property features | Continuous numeric EDA |
| Discrete count features | Count and zero-heavy EDA |
| Ratio/rate features | Ratio stability and extreme-value EDA |
| Date/duration features | Duration and signed-value EDA |
| Overdue/delay features | Payment behavior and delay EDA |
| Binary flags | Flag balance and rare-event EDA |
| Nominal/ordinal categories | Encoding and category-risk EDA |
| ID/TARGET | Exclude from feature analysis |
